What is Google Antigravity?

Google Antigravity is an agent-first IDE released in public preview November 2025, built as a fork of VS Code and powered primarily by Gemini 3.1 Pro. It is Google's answer to Cursor and AWS Kiro — but with a heavier emphasis on fully autonomous multi-agent workflows. It was built largely by the former Windsurf IDE team acquired by Google in 2025.

The name has a double meaning: import antigravity in Python opens XKCD comic #353 about Python making impossible things effortless.

ℹKey distinction from Cursor/Copilot: Antigravity agents don't just suggest code — they autonomously open the terminal, install packages, edit multiple files, launch a browser to test your app, observe the result, and self-correct. You assign a goal, not a line of code.

Two paradigm shifts from Spyder

1. From cells to agents. In Spyder you run # %% cells interactively. In Antigravity you describe a task and an agent plans and executes it. You can still run cells — but agents generate, refactor, and explain code far faster.

2. From IPython console to Artifacts. Spyder's variable explorer and console are replaced by the Artifacts panel — a structured log of the agent's reasoning, intermediate outputs, browser screenshots, and task lists. Your execution trace is now a document, not a scrolling terminal.

02

Install & First Launch

1

Download the installer

Go to antigravity.google → Download for your OS. Requires 8 GB RAM minimum, 16 GB recommended. 64-bit only.

2

Run installer → select Start Fresh

Choose theme. You can import existing VS Code settings if you have any.

3

Choose Agent Manager mode

Choose Agent-Assisted Development (recommended for scientists). See Section 05 for details.

4

Sign in with Google account

Free tier: generous rate limits on Gemini 3.1 Pro, refreshed every 5 hours. No credit card during preview.

5

Open your project folder

File → Open Folder. Antigravity reads your existing .py, requirements.txt, pyproject.toml automatically.

6

Set Python interpreter

Bottom status bar → click Python version → Select Interpreter → pick your conda/venv. Do this before your first agent task or it may install packages in the wrong place.

⚠Virtual environment gotcha: The first agent run may ignore your existing venv and install packages globally. Always verify the interpreter is set first. A security researcher flagged a backdoor vulnerability in late Nov 2025; Google is patching — keep Antigravity updated.

Editor View vs Manager View

Editor View is your standard single-project coding environment (use this 90% of the time). Manager View is a control centre for running multiple agents in parallel — e.g. one agent refactoring while another writes tests simultaneously.

05

Agent Modes

The most important configuration choice. Set it during install but change it any time in Settings → Agent Manager Policy.

Agent-Driven
Full autopilot. Agent writes code, runs terminal commands, edits files without asking. Fastest but least control.
Use for: scaffolding new projects, one-shot experiments, boilerplate
Agent-Assisted Recommended
You stay in control. Safe automations run automatically; destructive or ambiguous actions ask permission. Best balance.
Use for: scientific coding, refactoring, daily development work
Review-Driven
Agent asks permission before almost every action. Slowest but maximum oversight.
Use for: clinical data pipelines, production code, sensitive work

Plan Mode vs Fast Mode (per-task setting)

ModeWhat happensBest for
Plan ModeAgent generates a full task plan (Plan Artifact) before acting. You can edit the plan before execution starts.Multi-file refactoring, new features, complex pipelines
Fast ModeExecutes immediately. No plan artifact. Much faster for simple operations.Quick fixes, single-file edits, explaining code

Terminal Policy

Configure separately: Auto (run standard commands freely), Agent Decides (agent judges when to ask), or Always Ask. For scientific data work, Agent Decides is sensible — pip installs run automatically, but destructive commands require confirmation.

AI Models Available

Switch models mid-conversation from the dropdown in the agent sidebar.

Gemini 3.1 Pro (High)DefaultBest for complex multi-file tasks, large context (1M tokens), strong code reasoning. Primary model for all agentic operations.
Gemini 3.1 Pro (Low)AltFaster, lower token cost. Good for quick edits when you've hit rate limits on the High tier.
Gemini 3 FlashFastVery fast, lower quality. Good for boilerplate generation, simple refactoring, quick questions.
Claude Sonnet 4.5AltStrong for scientific Python, nuanced reasoning, documentation. Switch here if Gemini misunderstands domain-specific tasks (e.g. MNE/MEG).
Claude Sonnet 4.5 (Thinking)ReasoningExtended thinking mode. Best for complex algorithm design, debugging hard logic errors. Slower but more thorough.
GPT-OSS 120B MediumOpenOpen-source option. Useful if you prefer not to use proprietary models for sensitive data.
ℹRate limits: All models are free during preview with limits refreshed every 5 hours. Heavy use will exhaust Gemini 3.1 Pro limits — switch to Flash or Claude Sonnet to continue. Bring-your-own-API-key is not yet supported.

Setting up your conda/venv environment

Terminal
# Option A — conda (recommended for scientific Python)
conda create -n myenv python=3.11
conda activate myenv
pip install mne numpy scipy matplotlib

# Option B — venv
python -m venv .venv
source .venv/bin/activate    # Linux/macOS
.venv\Scripts\activate       # Windows

# Then: Ctrl+Shift+P → "Python: Select Interpreter" → pick env

Recommended settings.json

settings.json (Ctrl+Shift+P → "Open User Settings JSON")
{
  "python.terminal.activateEnvironment": true,
  "jupyter.sendSelectionToInteractiveWindow": true,
  "jupyter.interactiveWindowMode": "perFile",
  "editor.formatOnSave": true,
  "python.formatting.provider": "black",
  "python.analysis.typeCheckingMode": "basic",
  "files.autoSave": "afterDelay",
  "files.autoSaveDelay": 1000
}

Debugger setup (replaces Spyder's F12)

.vscode/launch.json — create this in your project root
{
  "version": "0.2.0",
  "configurations": [{
    "name": "Python: Current File",
    "type": "debugpy",
    "request": "launch",
    "program": "${file}",
    "console": "integratedTerminal",
    "justMyCode": true,
    "env": {"PYTHONPATH": "${workspaceFolder}"}
  }]
}

After this, F9 sets breakpoints inline, F5 launches the debugger.

Agent Prompting Guide

The quality of agent output is almost entirely determined by how you phrase the task. These patterns work well for scientific Python.

Effective prompt examples

✦ Refactoring

"Refactor pseudoMRI.py to replace all bare print() calls with logging.info() and logging.debug(). Use the existing logger = logging.getLogger(__name__) pattern. Do not change any scientific logic. Show me a diff before applying."

✦ New function

"In riemannsep.py, add a method called export_denoising_matrix() that saves self._D as a .npy file and writes metadata (threshold, mode, timestamp) to a companion JSON. Follow the existing code style. Add a NumPy-style docstring."

✦ Debugging

"This function raises a LinAlgError on ill-conditioned covariance matrices. Find the cause, add a regularisation fallback using np.eye(n) * 1e-6 * np.trace(C) / n, add a logger.warning when it fires. Show me the fix before applying."

✦ Explaining unfamiliar code

"Explain what the _jacobi_ajd function does, in plain language suitable for a signal processing researcher who knows matrix algebra but has not seen joint diagonalisation before. Include a worked 2x2 example."

✦ Writing tests

"Write pytest unit tests for the _riemannian_whitening function. Test that: (1) W @ C @ W.T is approximately identity, (2) function handles near-singular C without raising, (3) output shape matches input. Use np.testing.assert_allclose."

✦ Performance

"Profile the apply() method using cProfile on MNE sample data. Identify the top 3 bottlenecks. Propose vectorised numpy alternatives for any Python loops. Show proposed changes before applying."

Prompting rules

DoAvoid
Be specific about file and function namesVague: "fix the bug in my code"
Say "show me the diff before applying" for risky changesLetting the agent overwrite without review
Specify: "follow existing code style in file"Letting the agent invent its own style
Say "do not alter the scientific logic"Open-ended tasks on critical pipelines
Use Plan Mode for multi-file changesFast Mode for large refactors
Switch to Claude Sonnet for MNE/MEG-specific tasksStaying on Gemini if it misunderstands domain concepts

Scientific Python Tips (MNE / NumPy / SciPy)

Interactive plots (Spyder-style)

Use %matplotlib widget in a Jupyter notebook for interactive, zoomable plots. Use %matplotlib inline for static plots. In .py files, add plt.show(block=True) to keep the window open.

Variable inspector

In .ipynb notebooks, open the Jupyter Variables panel (View → Jupyter Variables). In .py files, set a breakpoint and inspect variables in the debug Watch panel — closest to Spyder's variable explorer.

Spyder-style cells in .py files

The # %% cell marker still works. Run cells with Ctrl+Enter. Open the Jupyter Interactive Window (Shift+Enter on selection) for an IPython-like REPL tied to your .py file.

Large array inspection

Add a temporary cell: # %% debug with print(arr.shape, arr.dtype, arr.min(), arr.max()). Or ask the agent: "add a debug cell after line 47 that prints shape and stats of X".

MNE interactive plots

MNE interactive plots need a Qt backend. Add import matplotlib; matplotlib.use('Qt5Agg') at the top, or set "jupyter.themeMatplotlibPlots": true in settings for notebook rendering.

Conda env in terminal

If conda env doesn't activate automatically, add to settings.json: "python.terminal.activateEnvInCurrentTerminal": true. Or manually run conda activate your_env in the integrated terminal.

Agent for data exploration

Ask: "add a cell that loads the .fif file, prints info, and plots the first 10 seconds of gradiometer data". The agent will write and run it — faster than typing it yourself.

Import errors after agent install

If the agent installed a package but import fails, it likely used the wrong env. Check with which python in terminal and verify it matches the selected interpreter at the bottom status bar.

Safety, Gotchas & Limitations

🔴Security vulnerability (Nov 2025): Mindgard research flagged a potential backdoor attack vector in Antigravity. Google is patching. Keep the IDE updated, use Review-Driven mode on sensitive codebases, and do not open untrusted project folders.
⚠Virtual environment confusion: The agent's first instinct is to install packages globally. Always set the Python interpreter before running any agent task. Keep a requirements.txt in the project root — the agent will respect it.
⚠Rate limit cooling: Gemini 3.1 Pro limits refresh every 5 hours. Keep Claude Sonnet as a fallback. Heavy multi-agent Manager View sessions drain limits faster than single-agent work.
⚠Agent overconfidence on scientific code: The agent may confidently refactor MNE-specific code incorrectly. Always specify your MNE version in prompts for version-sensitive API calls.
ℹNo paid tiers yet: As of May 2026, bring-your-own-API-key and paid plans are not supported. You cannot use your own Anthropic or Google AI credits inside Antigravity.
✦Undo is your friend: Every agent change can be undone with Ctrl+Z or from the Artifacts panel → "Revert this change". Antigravity also auto-creates a Git checkpoint before any multi-file agent operation in Plan Mode.
